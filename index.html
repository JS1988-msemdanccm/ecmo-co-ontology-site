ECMO-CO

ECMO Circuit Ontology

An OWL domain ontology under BFO 2020 for the structure of an ECMO circuit: its components and ports, the directed connections between ports, and the lumens inside a cannula. It represents two things the ECLS Common Data Model does not capture — port-level directed connectivity and per-lumen cannula structure.

The Problem

What the ECLS Common Data Model does not capture

The ECLS Common Data Model (an OMOP CDM extension; table definitions as retrieved May 2026) records an ECMO circuit's components as a membership list and each cannula as a single row. It does not capture:

  • Port-level directed adjacency — which component port feeds which, and the order of the components between the drainage and return cannulae. ecls_circuit_component lists circuit membership with no port, no order and no second component.
  • Sub-cannula lumen structure — the drainage or return role and fenestrations of each lumen of a multi-lumen cannula. ecls_cannula holds one row with one flow direction per cannula; dual-lumen is a cannula device type, with no per-lumen record.

The gap runs both ways: the ECLS CDM has dedicated columns for facts that ECMO-CO Phase 1 has no property for — run urgency as a concept code (ecls_run.urgency_concept_id), the cannula product's name and manufacturer as text (ecls_cannula_material.name, manufacturer) and cannula size as an integer French size (ecls_cannula_material.diameter_in_french) — which the ECMO-CO scenarios carry at most in free-text labels.

The Solution

A domain ontology under BFO 2020

ECMO-CO is an OWL ontology that represents ECMO circuit structure as machine-readable data. Phase 1 scope:

  • Static circuit topology: components, segments, ports, connections
  • Lumen mereology: LumenConduit (material) paired with CannulaLumen (site)
  • Role/function distinction on cannula lumens across temporal epochs
  • Configuration records as generically dependent continuants (GDC)
  • 4-layer validation: OWL parse → OWL-RL closure → SHACL → SPARQL CQ probes

Phase 2 is planned to add sensor/observation (SOSA), provenance (PROV-O) and measurement units (QUDT); see the stack table below.

Concrete example — how the circuit is connected

✗ What the ECLS CDM records — and does not capture

Records: which components belong to each circuit (ecls_circuit_component) and each cannula's flow direction (flow_direction_concept_id). Its concept releases also include concepts for membrane lungs in series or in parallel, for measurements whose concept carries its own position (pre- and post-membrane lung pressure, pump inlet pressure, membrane lung pressure drop), and for where a renal replacement therapy circuit is attached relative to the membrane lung and blood pump.

✗ Does not capture: which component feeds which, through which port, or the order of the components between the drainage and return cannulae. No ECLS CDM extension table or column links one component to another, and none of its concepts names such a link: the position-bearing concepts above place a measurement or an attachment point, and the series and parallel concepts do not say which membrane lung feeds which.

✓ What ECMO-CO represents

Each junction is recorded by an ecmo-co:CircuitConnection: an information record of the directed mating of an upstream ecmo-co:Port to a downstream one. It points to the ecmo-co:CircuitInterface, the relational quality that both ports bear while they are mated. Each port is part of its component. Chaining the connections port to port gives the flow order: femoral cannula → drainage tubing → blood pump → oxygenator → return tubing → IJ cannula.

:CC_Pump-Oxygenator a ecmo-co:CircuitConnection ;
    ecmo-co:hasUpstreamPort     :Port_Pump_outlet ;
    ecmo-co:hasDownstreamPort   :Port_Oxy_inlet ;
    ecmo-co:connectionInterface :PI_Pump-Oxygenator .
:Port_Pump_outlet a ecmo-co:Port ; bfo:0000176 :Pump_Centrifugal_01 .
:Port_Oxy_inlet   a ecmo-co:Port ; bfo:0000176 :Oxygenator_PMP_01 .
:PI_Pump-Oxygenator a ecmo-co:CircuitInterface .

Excerpt from the synthetic VV femoral–IJ scenario; namespace declarations omitted. bfo:0000176 is BFO's “continuant part of”. The order is derived by following the connections; no ordinal value is stored. Component names come from the scenario's text labels: the ECLS CDM records cannula site (coded) and size, which this scenario states only in text.

Concrete example — inside a dual-lumen cannula

Note: the ECLS CDM's table definitions and concept releases support the per-lumen capture gap shown below; its clinical value has not yet been demonstrated.

✗ What the ECLS CDM records — and does not capture

Records: each cannula as an ecls_cannula row with one flow direction (which may be “drainage and return”), one coded site and one coded tip position. Its concept releases also include cannula-type concepts: single-lumen, dual-lumen, and single-lumen with an integrated distal perfusion outlet.

✗ Does not capture: the parts inside a cannula — which lumen drains and which returns, and which fenestrations belong to which lumen. No ECLS CDM extension table has a lumen-level row, and no table, column or concept names a fenestration.

✓ What ECMO-CO represents

The cannula has two ecmo-co:LumenConduit parts. One bears ecmo-co:DrainageFunction and ecmo-co:DrainageRole; the other bears ecmo-co:ReturnFunction and ecmo-co:ReturnRole. Each ecmo-co:CannulaFenestration is part of one lumen conduit and ecmo-co:opensInto that conduit's ecmo-co:CannulaLumen: two on the drainage conduit, one on the return conduit.

:LumenConduit_AVALON_Drainage a ecmo-co:LumenConduit ;
    bfo:0000176   :Cannula_AVALON_27Fr ;
    ecmo-co:bears :DrainageFunction_AVALON , :DrainageRole_AVALON_Epoch1 .
:LumenConduit_AVALON_Return a ecmo-co:LumenConduit ;
    bfo:0000176   :Cannula_AVALON_27Fr ;
    ecmo-co:bears :ReturnFunction_AVALON , :ReturnRole_AVALON_Epoch1 .
:CannulaFenestration_AV_RA a ecmo-co:CannulaFenestration ;
    bfo:0000176       :LumenConduit_AVALON_Return ;
    ecmo-co:opensInto :CannulaLumen_AVALON_Return .

Excerpt from the synthetic AVALON dual-lumen scenario; namespace declarations omitted. bfo:0000176 is BFO's “continuant part of”. Fenestration placement appears only in the scenario's text labels and identifiers; the ECLS CDM codes cannula site and tip position.

Cannulation Modes
  • V-V (standard two-site: femoral/IJ)
  • V-A (peripheral: femoral/femoral)
  • V-AV (femoral-vein drainage; return to the femoral artery and the right internal jugular vein)
  • AVALON dual-lumen (single-site IJ)
  • ECPR (emergency V-A)
Complex Topologies
  • Multi-epoch V-V → V-A configuration change
  • Parallel oxygenators (same V-V mode, serial → parallel topology)
  • Dual concurrent circuits
  • Full circuit change (pump, oxygenator and tubing replaced; cannulae kept)
  • CRRT integration (adjunct non-ECMO device)
  • Impella co-management (venting device)
  • INVALID negative fixture (confirms SHACL rejection)
