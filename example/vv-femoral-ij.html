Clinical Scenario

V-V ECMO — Refractory ARDS, Two-Site Femoral/IJ Cannulation

Adult patient with severe refractory ARDS. Standard two-site veno-venous circuit:

  • Drainage: right common femoral vein, 25 Fr single-lumen cannula
  • Return: right internal jugular vein, 21 Fr single-lumen cannula
  • Single pump (centrifugal), single PMP oxygenator
  • One stable configuration epoch from cannulation to decannulation (8 days)
Key ECMO-CO Features in This Scenario
Full port-to-port topology — 5 reified CircuitConnection GDC records encode every directed connection: femoral cannula → drainage tubing → pump → oxygenator → return tubing → IJ cannula
Function vs Role on each LumenConduit — DrainageFunction (rigid, from manufacture) + DrainageRole (anti-rigid, from configuration) on the femoral lumen conduit; analogous for IJ
CannulaLumen as BFO:Site — the immaterial interior channel is a Site. BFO requires a material bearer for a Function (BFO 2.0 Reference [062-002], [064-001]), so the Site cannot bear one; the same Reference also requires a material bearer for a Role ([063-002]), and ECMO-CO policy keeps Roles off it in any case. The bounding LumenConduit (FiatObjectPart) is the function- and role-bearer
CircuitInterface (SDC) — each port mating is a relational quality jointly borne by two Port individuals, transient while mated; the corresponding CircuitConnection GDC persists afterward. The two-Port requirement belongs to CircuitInterface, not to the parent PhysicalInterface — a DeviceTissueInterface is borne by a cannula and an anatomical entity, with no Ports involved

SPARQL — List the Circuit Path

Returns the five directed port-to-port connections asserted by the run's configuration epoch, sorted by their labels, which number them in flow order from the drainage cannula to the return cannula.

# Namespace declarations omitted.
SELECT ?conn ?upPort ?downPort
WHERE {
  ?run     ecmo-co:hadConfigurationEpoch  ?config .
  ?config  ecmo-co:assertsConnection      ?conn .
  ?conn    ecmo-co:hasUpstreamPort        ?upPort ;
           ecmo-co:hasDownstreamPort      ?downPort ;
           rdfs:label                     ?label .
}
ORDER BY ?label
?conn | ?upPort | ?downPort ------------------------|-----------------------------|------------------------------ :CC_Fem-DrainageTubing | :Port_Fem_distal | :Port_DrainageTubing_proximal :CC_DrainageTubing-Pump | :Port_DrainageTubing_distal | :Port_Pump_inlet :CC_Pump-Oxygenator | :Port_Pump_outlet | :Port_Oxy_inlet :CC_Oxy-ReturnTubing | :Port_Oxy_outlet | :Port_ReturnTubing_proximal :CC_ReturnTubing-IJ | :Port_ReturnTubing_distal | :Port_IJ_distal
SPARQL — Function/Role Pairs per LumenConduit

Lists each LumenConduit's design Function next to its configured Role, so an off-design assignment would show as a mismatched pair.

# Namespace declarations omitted.
SELECT ?lumen ?fnType ?roleType
WHERE {
  ?lumen  ecmo-co:bears  ?fn , ?role .
  ?fn     rdf:type   ?fnType .
  ?role   rdf:type   ?roleType .
  FILTER( ?fnType  IN (ecmo-co:DrainageFunction, ecmo-co:ReturnFunction) )
  FILTER( ?roleType IN (ecmo-co:DrainageRole,    ecmo-co:ReturnRole) )
}
ORDER BY ?lumen
?lumen | ?fnType | ?roleType ------------------|--------------------------|--------------------- :LumenConduit_Fem | ecmo-co:DrainageFunction | ecmo-co:DrainageRole :LumenConduit_IJ | ecmo-co:ReturnFunction | ecmo-co:ReturnRole
